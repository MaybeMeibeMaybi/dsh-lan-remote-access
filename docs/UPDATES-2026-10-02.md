## 2. 为什么 `detached` 这么重要

Windows 上 `spawn("powershell.exe", …, { detached: true })` **什么都不做也不会报错**：
没有异常、没有日志、进程就是不出现。改成 `detached: false` 再 `unref()` 之后一切正常。
现在的做法是：先探测（端口/进程），再拉起，**并在 15 秒后复核一次"还在不在"**，
把"拉起来了但立刻死了"这种失败模式变成日志里可见的一行。

## 3. 局域网入口的三层自检

看门狗每 30 秒做一次真请求，而不是只看端口在不在：

1. `GET http://<lan-ip>:3081/?token=<本次 token>` → 期待 `303`（会话引导）；
2. 带 cookie jar 跟随到 `/` → 期待 `200` 且拿到真实 GUI 页面；
3. 结果写进 `local-gateway-watch.json` 的 `lanEntry` 字段，异常才写日志（避免刷屏）。

另外新增了 **`stateFresh`**：`web-state.json` 里记录的 pid 必须等于当前监听 3080 的 dsh 进程，
否则判为"陈旧状态"。这一条来自真实事故：陈旧文件里的旧 token 让卡片投递检查**误判成功**，
而且一旦触发兜底补推，会把**已经失效的 token** 推给用户手机。现在遇到陈旧状态就明确写
`stale-state`，而不是给出一个误导性的 401。
